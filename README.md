# Mr. Finance

*Khách hàng có tài sản ở nhiều sản phẩm, nhiều kênh, nhiều nền tảng, nhưng không ai cho họ thấy bức
tranh toàn cảnh. Mr. Finance làm việc đó, và cho biết điều gì đang tác động tới bức tranh ấy.*

One picture of a client's wealth — Techcombank's own products, other banks and brokers, and what the
client declares — and what is moving it: policies, the market, infrastructure, their own life. A
working demo of the brief in [`mr_finance_idea_final.md`](mr_finance_idea_final.md), built on
[operonx](https://pypi.org/project/operonx/) and operonx-agents. Every number is computed by an
operonx graph from mock data for five sample clients.

> **Coding assistants:** start at [`AGENTS.md`](AGENTS.md), then [`docs/PLAN.md`](docs/PLAN.md).

## Run it

With uv:

```bash
uv sync
uv run pytest                  # offline, ~20 s
uv run operonx serve           # http://127.0.0.1:8030
```

With pip (no uv):

```bash
python -m venv .venv && . .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -e ".[test]"
pytest
operonx serve
```

Then open <http://127.0.0.1:8030>. [`docs/DEMO.md`](docs/DEMO.md) is the five-minute demo, step by step.

**AI.** Reading an uploaded statement and the chat that records declarations use a model when one is
configured (`cp .env.example .env`, set `LLM_API_KEY`; any OpenAI-compatible endpoint). Without one,
every AI step takes its rule path, so the demo runs anywhere. `MF_AI=on|off|auto` forces it.

## What it does

| Page | What it shows | The graph behind it |
|---|---|---|
| **Tổng quan** | net worth and its month change, the trust mix, allocation, P&L against the benchmark, the drawdown limit against a stress estimate, concentration, liquidity in months, the past 6 months' cash flow and a 12–36 month forecast (lighter), the top alerts | `dashboard_flow` |
| **Kết nối dữ liệu** | three tiers of sources, every holding grouped by asset class (purchase date, price, cost, profit) with its trust label; upload a statement (PDF, Excel, CSV); declare by chat | `consolidate_flow`, `statement_flow`, `declare_flow` |
| **Cảnh báo** | 14 policies, macro moves and infrastructure projects scored on the client's holdings: impact = exposure × sensitivity × probability, with sources; house views (research houses' forecasts, mock) matched to the holdings | `alerts_flow` |
| **Bài test rủi ro** | 8–12 adaptive situational questions; tolerance against capacity; one of five personas | `risk_flow` |
| **Kịch bản** | 9 life events and 5 stress tests on the client's own data, each with a light and a heavy option | `scenario_flow` |
| **RM duyệt** | the queue of options waiting for an RM's approval | `review_flow` |

The services, jobs and the eval are all in [`app/main.py`](app/main.py):

```bash
uv run operonx serve --list    # 8 HTTP services, the 07:00 sweep, the web app
uv run operonx run --list      # policy_sweep (every client's alerts), statement_reading (an eval)
```

See every graph drawn, run and traced with [operonx-studio](https://github.com/batman1m2001-cyber/operonx-studio):
`uv run operonx studio`.

## The data

Everything under `data/` is generated by the scripts in `scripts/` and is **mock**: five clients and
two spouses, the market on 2026-10-09, sample statements, and the policy list. Prices, rates and bond
issuers are invented. The policies' legal status is a snapshot: check each one before a real demo,
as the brief says. What a client adds in the demo (statements, declarations, risk tests, the RM
queue) is kept in `data/state.db`; **Làm lại demo** in the footer empties it.

Nothing here is investment advice: the product says so on every simulation, and an RM approves
before anything is recommended.
